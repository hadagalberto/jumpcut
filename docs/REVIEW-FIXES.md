# Independent review findings — fix report

All items were fixed root-cause. Each item first got a regression test with a
hand-derived expected value (from the official format documentation, the SPEC,
or explicit reasoning in the test comment); the test was observed failing
before the code was changed.

| Finding | Regression test(s) | Fix summary | Status |
| --- | --- | --- | --- |
| **HIGH** — Premiere xmeml v4 structure wrong (`premiere.rs`): bare `<track>` under `<sequence>`, bare `<rate>`, per-clip `<file>`, file duration = clip out point, two `<timecode>` elements | `premiere_xmeml_v4_follows_apples_documented_hierarchy`, `premiere_uses_ntsc_rate_structure_and_one_media_file`, `file_duration_is_the_full_media_length`, `drop_frame_sequence_uses_ntsc_flag_and_source_timecode`, `sample_characteristics_use_probed_dimensions` (integration: `tests/nle_schema.rs`) | Rewrote exporter to Apple's documented hierarchy: `<sequence> → <media> → <video>/<audio> → <track> → <clipitem>`. Added A/V `<link>`s. | **Fixed** |
| **HIGH** — FCPXML 1.10 claims 1.10 but writes `<asset src=...>` and a `<format ref>` child; retime uses non-DTD `timePt` | `every_generated_fcpxml_validates_against_apples_1_10_dtd`, `fcpxml_asset_uses_media_rep_and_format_attribute`, `fcpxml_speedup_uses_the_dtd_named_timept_element`, `dtd_validator_rejects_the_documented_bad_fcpxml_constructs` (`tests/nle_schema.rs`) | Apple's 1.10 DTD is vendored verbatim in `tests/fixtures/FCPXMLv1_10.dtd` and a DTD-driven validator (entity expansion, content models, ATTLIST/enum/ID/IDREF checks) validates every generated document. `<asset>` now uses `format="rFmt1"` plus `<media-rep kind="original-media" src="..."/>`; `<timePt>` → DTD-correct `<timept>`. | **Fixed** |

## Test-oracle and snapshot notes

- The old snapshot files locked in the FCPXML, Premiere and OTIO defects. All
  affected snapshots were regenerated and **read back** and checked against the
  documentation: `fcpxml`, four `fcpxml_format_*`, `premiere`, `otio`.
- Existing assertions that encoded a listed bug were corrected in place with a
  comment citing the reason: Premiere's width count (4 → 2), its second
  `<timecode>` expectation (`00:00:02;00` → single `00:00:00;00`), and OTIO's
  `media_reference` → `media_references.DEFAULT_MEDIA` path. No test was
  deleted, skipped or loosened.
- FCPXML validation does not trust a snapshot or an oracle generated by the
  exporter: the oracle is the vendored Apple DTD, parsed independently by the
  test. A dedicated negative test proves the validator rejects the old
  constructs. Premiere and OTIO use hand-written checks from Apple's/OTIO's
  published element and field lists.
- Verification: `cargo test --workspace`, `cargo fmt --all -- --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`.
